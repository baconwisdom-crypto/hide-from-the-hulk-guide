# Reuse validation

The framework was based on the latest common implementation in `E:\网站` and the locale files in `E:\网站-i18n-draft`.

## Reused and adapted capability

1. Guide article shell with anchored sections, tables, cards, FAQ, spoiler boundary, and related pages.
2. Header, mobile navigation, footer, breadcrumbs, sidebar, bottom-only official source list, status badge, page header, table of contents, JSON-LD, content image, and video embed components.
3. App Router metadata, robots, sitemap, trailing-slash URLs, and static route checks.
4. A single required `searchVisibility` contract shared by metadata, robots, sitemap, and publisher checks.
5. Locale configuration, dictionary loading, locale labels, language tags, and localized URL helpers.
6. Source-linked evidence rows that retain public URLs and verification labels.
7. A single homepage action: the `PageAction` type, a generic `ActionCard` with one semantic primary button, and locale-aware `next/link` rendering. The label and target live in `content/pages.json`, not in components. A derived game site points that action at its Getting Started overview or hub, or at the first beginner guide when no hub exists; the shared components never hardcode the path or the English label.
8. A required first-party brand icon contract, deterministic favicon generation, root `metadata.icons`, Header image fallback, and exact output validation for `favicon.ico`, `icon-192.png`, and `apple-touch-icon.png`.
9. A restricted inline SVG navigation icon set, configuration-layer `navigationIcons` mapping, stable fallback resolution, shared desktop/mobile disclosure content, `aria-current` route state, and token-based hover, focus, active, and expanded feedback.
10. A full-name Header contract with a real configured mark by default, an image-failure fallback, a separate navigation row, and a responsive article-media rule that stacks video-ratio screenshots while compact media may use multiple columns.
11. A shared `page-content` main container with tokenized responsive padding, homepage hero variants for compact square art and wide video media, and a public-site guard against an empty homepage media configuration.
12. A document-flow Header contract that leaves the viewport on scroll while preserving sticky WikiSidebar and article table-of-contents roles.
13. A standard sidebar shell contract that keeps `px-4 sm:px-6`, `lg:grid-cols-[15rem_minmax(0,1fr)]`, and `page-content` exclusively on the main content container so the visible WikiSidebar does not receive main-column padding.

## Validation boundary

The framework example uses neutral records and Next.js documentation only. It contains no game characters, plot, screenshots, or source-specific game copy. `npm run verify` checks the neutral registry, contract fixtures, TypeScript, build output, internal references, and SEO wiring.

The contract tests reject more than three page-level public sources, public use of internal-only evidence, unsupported hero types, hero media tied to a non-official source, missing or invalid `searchVisibility`, missing or non-official brand icon sources, non-square brand input, missing generated icon outputs, unsupported navigation icon names, public placeholder site URLs, Header fixed positioning, Header truncation, missing full-name wrapping protection, missing decorative image semantics, stale half-column image sizes, missing `page-content` containers or placement, an altered standard sidebar grid or shell inset, `page-content` on WikiSidebar, unsupported homepage hero variants, and a public site with no homepage hero image or video. Confirmed production Vercel aliases remain valid; preview, staging, test, or demo aliases fail. They also reject a published `Home` page without a `primaryAction`, a `primaryAction` that sets both or neither of `pageId` and `href`, a label that is missing, a page id that does not resolve to a published page, and an href that does not resolve to a published in-site route. Build checks reject repeated public source blocks, public source blocks above related content, retired section-source or media-attribution copy, visible image text while the default switch is off, missing brand icon metadata, missing Header brand mark output, missing Sidebar `aria-current`, and metadata, robots, or sitemap output that conflicts with the selected visibility. The primary-action fixtures use `Getting Started` only as an example label and never decide correctness from an English string; the rendering contract instead checks that `ActionCard` renders the caller-supplied label without a hardcoded path.

For each derived game site, first follow `MIGRATION-BRAND-ICONS.md` and `MIGRATION-LAYOUT.md`, run `npm run generate:brand-icons`, and run `npm run verify`. Then verify the homepage and one image-bearing article on desktop, tablet, and a 320px viewport. Confirm the full site name remains available, the configured brand icon appears by default, direct requests for all three generated icon paths succeed, one icon appears per top-level Sidebar summary, no horizontal overflow occurs, keyboard-visible focus works, expanded and active states are visible, the main content uses `page-content` padding, square homepage art is visibly narrower than wide video media on desktop, both media variants remain full-width on mobile, video-ratio screenshots form a single-column vertical stack, compact media can use multiple columns, approved official hero media stays at the top without an outer card, no text appears below hero or article images under the default setting, and one official source block remains at the bottom. A public site with both hero fields empty must fail before release; the neutral preview may emit the documented warning.
