# Game Guide Framework layers

This project separates reusable rendering from game configuration and content.

## Framework layer

`app/` contains the default English route group, locale-prefixed route group, metadata files, and 404 handling. `components/` contains the shared shell, article renderer, bottom-only official source list, spoiler badges, table of contents, media blocks, locale switcher, brand mark fallback, inline navigation icons, preset ad-slot renderer, and the shared desktop/mobile sidebar content. `lib/` resolves the registry, builds navigation, resolves configured navigation icon keys with a stable fallback, creates canonical and alternate URLs, loads dictionaries, and provides source and brand icon helpers. `scripts/` validates the contracts and production output, including the exact brand icon asset set and the required ad-slot placements.

The reusable UI foundation also belongs to this layer. `app/globals.css` defines the three-level primitive, semantic, and component token system for typography, spacing, readable measures, control hit areas, radii, motion, focus rings, elevation, brand marks, navigation states, page-content padding, and homepage media widths. Shared components consume the `ui-surface`, `ui-interactive`, `ui-control`, `ui-button`, and navigation role tokens. Both route layouts keep the `px-4 sm:px-6` shell padding, the `lg:grid-cols-[15rem_minmax(0,1fr)]` sidebar track, and the `page-content` class exclusively on `main`, giving the page header, media, cards, and notices a safe responsive inset without narrowing the WikiSidebar. `NavigationIcon` is a small inline SVG component with a restricted `NavigationIconName` type. `SiteBrandMark` renders the configured square source and keeps a short-name fallback when an image cannot load. The Header stays in normal document flow so it leaves the viewport during page scroll, while WikiSidebar and the article table of contents retain their intentional sticky roles. The Header reserves a separate row for the full site name and navigation, with narrow-width wrapping and mobile menu behavior. Home media selects `compact-square` or `wide-video`, with square art capped near 26rem on desktop and full-width behavior on mobile. Article media keeps video-ratio screenshots in a full-width vertical stack and uses compact grids for square, portrait, or contained media. The generic `ActionCard` renders one deliberate action from caller-supplied copy and a locale-aware target, so it hardcodes no path and no English button text. Game-specific colors, imagery, textures, and ornamental treatments stay outside these foundation roles.

## Configuration layer

`config/site.ts` owns the site name, slug, domain, required `searchVisibility` contract, theme, confirmed first-party `brandIcon`, top-level `navigationIcons` mapping, supported and published locales, official links, approved official hero media, optional homepage media presentation variant, image-text presentation setting, analytics, ads, evidence labels, and disclaimer. `ads.desktopChrome.enabled` is the single rollback switch for the top and left sticky ad chrome. A game project replaces these values. `brandIcon.src` points to one confirmed local square game icon and `brandIcon.sourceId` points to an `official-first-party` source record. Generated outputs always use the fixed paths `public/favicon.ico`, `public/icon-192.png`, and `public/apple-touch-icon.png`. The brand icon is kept separate from `heroImage`, which remains approved key art or promotional media. Image text is off by default. Hero media must carry an approved official media type and first-party source ID. Public visibility also requires at least one approved homepage hero image or video.

## Content layer

`content/pages.json` is the page registry. `content/sources.json` is the source index. `content/routes.json` is the small route availability index consumed by the client locale switcher. Page records own navigation labels, sections, evidence IDs, images, spoiler levels, related page IDs, locale availability, publication status, up to three public official source IDs, and an optional `primaryAction`. Page records do not own visual navigation icon names. A published `Home` page must configure exactly one `primaryAction` here, pointing at a registered page id or an in-site route; the copy and target stay in this layer so a derived game site can change its single call to action without editing components. A derived game site points its Home `primaryAction` at that game's Getting Started overview or hub, or at the first beginner guide when the game has no hub. Components never hardcode the path or the English label. Source records explicitly classify public first-party sources and internal-only research evidence.

The framework fixes the generated icon asset paths and does not copy or scan the whole `public/` directory. Run `npm run generate:brand-icons` after placing the configured source file. The command accepts `--source` for an explicit local source and rejects remote URLs, non-square input, output paths outside the exact three targets, and source/output collisions.

Navigation, sitemap entries, related links, and locale links are derived from published page records. Planned and internal-hold records stay out of public navigation and sitemap output. `searchVisibility: "public"` enables indexable metadata, crawlable robots, and a sitemap containing published routes. `searchVisibility: "preview"` emits noindex, nofollow, and noarchive metadata, disallows crawling, and returns an empty sitemap. Public Vercel aliases are accepted only when they are confirmed production addresses rather than preview, staging, test, or demo placeholders.

Image labels, captions, media names, source URLs, video IDs, timecodes, screenshot bindings, section source IDs, competitor references, fan-wiki records, and third-party video evidence remain in the configuration or content layers. The default renderer exposes only alt text with the image and one official source block at the page bottom.
